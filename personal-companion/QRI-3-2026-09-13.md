# QRI-3 — standing filters, the third defect class (2026-09-13)

Author: qnfo-ops endpoint. Every figure is from a tool return in-session.
Builds on `FINDING-2026-09-13-standing-filters.md` (concurrent session, same day), which

## 1. The gap, and who found it

`grounding.js` checks quantities. `voice.js` checks attribution. `addressee.js` checks the
reader's name. None of them checks the reader's **standing filters** — the things he has
asked not to be sent.

`PERSONAL.profile` holds a `standing-filters` facet, and `loadProfile()` feeds every row
with `confidence >= 0.7` into the generation context. Verified read-only this session:

| confidence | label |
|---|---|
| 1.00 | agent-owned implementation decisions |
| 0.98 | No physics/science books in reading recommendations |
| 0.95 | No QPL/CWI topics in personal recommendations |

The writer is handed the QPL/CWI row and writes the topic anyway. Measured across all
seven live pieces (`instr(body_md,'QPL')`):

```
id 6  0 | id 7  0 | id 8  352 | id 9  0 | id 10  0 | id 11  0 | id 12  0
```

One piece. `companion_pieces.id=8` opens on QPL 2026 while the row forbidding QPL was in
force (dated 2026-08-25; the piece was published 2026-09-12). CWI: 0 in every piece.
Gleick: 0. Rovelli: 0.

This is a different class from the grounding and voice defects: a piece can be **fully
grounded, perfectly attributed, and still be something the reader asked not to receive.**

## 2. What was implemented

`lib/filters.js` — `checkStandingFilters(text, opts)`, composed into `runGate()` as a
**fourth blocking class** (`gate.js` rev 5).

The deny list is auditable: every term names the profile row it implements.

```
QPL, Quantum Physics and Logic, CWI, Centrum Wiskunde & Informatica
    <- "No QPL/CWI topics in personal recommendations" (conf 0.95)
Gleick, Rovelli
    <- "No physics/science books in reading recommendations" (conf 0.98)
```

Word-bounded and case-insensitive: `QPL` matches "QPL 2026" but not "QPLX"; `CWI` matches
the standalone token but not inside a longer word.

### Terms deliberately OMITTED, with the reason stated

The physics row names two titles: **"The Information"** (Gleick) and **"The Order of
Time"** (Rovelli). Both are generic English phrases. As substring terms they would block
correct prose — "the information is not recoverable" would match. That is precisely the
false-block failure mode `grounding.js` rev 2 and `voice.js` rev 2 each record. They are
excluded, and the exclusion is written into the module rather than left silent. Covering
them needs citation context (a title in italics, or a book-title pattern), not a phrase.

### NOT covered, and not claimed

The **CATEGORY** row — "no physics/science books" — cannot be enforced from a term list.
It needs a subject classifier and belongs one level earlier, at `pickTopic()`, before
anchors are fetched. The concurrent session reached the same split. `filters.js` enforces
the entity list only.

## 3. A bug caught before it could reach a deploy

The first draft of `filters.js` declared a top-level `const esc`. **`voice.js` already
declares a top-level `const esc`.** The deploy patcher strips `export `/`import` and
concatenates all modules into ONE scope, so that is a duplicate declaration and the
inlined worker **would not parse** — a dead worker, discovered at load.

Caught by the collision check (the same check QRI-2 ran), fixed by renaming to `fesc`,
and recorded in both files so it is not reintroduced. Verified after the fix:

```
top-level names across the five modules: 34
COLLISIONS: 0
unresolved gate.js rev 5 imports: 0
INLINED BUNDLE WILL PARSE: true
```

This is the second time this class of defect has appeared (QRI-2 hit it with
`blockingViolations`). The check is cheap and should be run whenever a module is added.
