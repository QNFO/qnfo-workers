# ROOT-CAUSE-CONTRACT-1: the kept design for agent_issues 1000419

Charter pillar: autonomy. Kept, not landed (OWNER-NO-LOOSE-ENDS-1: the issue stays open with its doer and closing probe; delete this directory in the pull request that lands the migration).

**The defect.** The management-personas workflow (`fleet_tasks` id `management-personas`, step `rc-file`) files `ROOT-CAUSE-1: <FAMILY> keeps recurring` tickets. Each is born with the generic contract (`remediation_contracts` class `issue-<id>`, status `superseded`, action starting `VACUOUS-PROBE-V3-1`), which the PROBE-NEEDED-1 filer does not count as live, so each ticket breeds a twin (read 2026-10-26: 10 ROOT-CAUSE tickets, 16 PROBE-NEEDED-1 tickets). The same workflow closes a ticket when its family stops recurring (`rc-close-evidence`, `rc-close`, view `v_root_cause_quiet`), but the ticket's contract does not say so.

**The design** (a design agent's work, 2026-10-26, verified in node:sqlite against DDL copied from live: 179 assertions, 29 mutants killed):
- `2026-10-26-root-cause-contract.sql`: the migration (backup tables for the workflow row and the contracts it arms, one arming UPDATE, one `json_insert` of the step `rc-contract` into the workflow, a Rollback line).
- The probe is a `d1-query` contract, status `active`, expected `0`, observed the family's `reopens_24h + opens_24h` in `issue_recurrence_now`, plus 1 while the ticket is under 24 hours old, plus 1 while the snapshot is empty. It reads the snapshot and never `v_root_cause_quiet`: that view hides a ticket whose own active contract reads `fail`, so a probe that waited for the view could never turn true (the deadlock the issue's first draft of the probe, `expected 1 / count of v_root_cause_quiet rows`, would have built).
- `backfill.sql`, `json_insert.sql`, `workflow_step.json`, `rollback.sql`: the statements as separate files; `schema.sql` is the fixture DDL; `build.mjs` assembles the migration from them; `test.mjs` is the suite (`node --no-warnings test.mjs` from this directory).

**Known cost, read before landing.** While a family is busy, or a ticket is under 24 hours old, the contract reads a real `fail`: about 6 probes an hour per contract (the tick every 18 minutes and the consumer every 22), roughly 1,400 failing `remediation_verifications` rows a day for 10 contracts. The guard metric `remediation_latest_pass_pct_7d` (trigger below 50, 78 on 2026-10-26) moves one to two points while they are busy. A standing `fail` also blocks every closer of the ticket through `issue_close_evidence_required`, as intended. The step is appended last (`json_insert` appends), so a run that aborts earlier skips it until the next hour. The design lists a TOCTOU between `rc-close-evidence` and `rc-close` (a `fail` to `pass` flip between the two statements aborts the run with `close-without-evidence`; window of seconds at a ticket's single transition, self-heals next hour).

**To land it.** Apply the findings of an independent review first (one was running when this was kept), move the suite to `migrations/root-cause-contract.test.mjs` reading the migration file instead of `build.mjs`, file the migration as a new `migrations/` file (MIGRATION-NO-CLOBBER-1 refuses an edit to a merged one), run `python3 scripts/apply_migrations.py --check` on it, and close 1000419 with the probe in its description (reads 0 once no open ROOT-CAUSE-1 ticket stands on a superseded contract).
