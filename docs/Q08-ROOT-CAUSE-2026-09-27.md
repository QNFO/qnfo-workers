The worker is healthy at its workers.dev origin. Only the custom domain is broken.

## 2. Root cause — zone-level Redirect Rule

Fingerprint: the 301 carries uppercase `charset=UTF-8` (rules-engine signature), no
`cf-cache-status`, no Pages headers. Real Pages responses on this fleet carry lowercase
`charset=utf-8` plus `public, max-age=0, must-revalidate`.

No repo worker emits a redirect for this host: `qnfo-web-unified/hub-worker.js` is 1161 B with
0 hits for `301` / `302` / `Location` / `redirect`. Its host map still contains
`'q08.org': {title:'QNFO', tag:'Research foundation'}`, but it is never reached.

Cloudflare's documented alias-domain pattern
(<https://developers.cloudflare.com/fundamentals/manage-domains/redirect-domain/index.md>)
is a proxied dummy A record (`192.0.2.1`) plus a Dynamic Redirect Rule with
`http.host eq "<alias>"`, status 301, preserving path — which is exactly the observed
behaviour except that this rule discards the path.

## 6. Required remediation (needs a zone-scoped credential)

1. `GET /zones?name=q08.org`, then read the `http_request_dynamic_redirect` ruleset for that
   zone and disable/delete the wildcard rule.
2. Remove q08.org and www.q08.org from the `qnfo-hub` Pages custom domains.
3. Deploy `q08-signal-engine` so the `q08.org/*` and `www.q08.org/*` routes install
   (PR #14, branch `fix/q08-route-and-archive-numbers`).
4. Re-probe `q08.org/` and a real `/p/<slug>` for 200 with the expected title.

## 7. Open sub-question (non-blocking)

Whether a Worker route beats a Dynamic Redirect Rule is **not documented** in any reachable
Cloudflare page. Checked: `rules/url-forwarding`, `rules/url-forwarding/bulk-redirects/how-it-works`,
`rules/snippets`, `fundamentals/concepts/traffic-flow-cloudflare`,
`workers/configuration/routing/routes`, plus the `rules/llms.txt` and `workers/llms.txt` indexes.
If the redirect phase precedes the Worker phase, step 3 alone is insufficient and step 1 is
mandatory. Either way step 1 must be done to get a clean test.
