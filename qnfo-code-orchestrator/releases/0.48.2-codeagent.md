# qnfo-code-orchestrator 0.48.2-codeagent (2026-11-05)

FLEET-STEP-DEADLINE-1: every fleet workflow step has a deadline (sql 60 s, http 45 s, ai 120 s, or the step's own deadline_ms) and a failing step is named in the run's error; a sql step the database rejects as overloaded is retried up to three times, 2, 4 and 6 s apart; the closing write of a run row (ok or failed) retries the same way, so a failure is recorded even while the refusal that caused it is in force; the audit event written after a run is best effort, so a refused insert no longer turns a finished run into a failed one. A stalled step no longer holds the dispatcher invocation, and a run no longer stays "running" because its failure could not be written.
