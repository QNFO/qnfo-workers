# Applier workflows manifest (TP-3a, issue 2019, APPLIER-WORKFLOWS-RETIRE-1)

Charter pillar: core. Classification of the 39 workflows under `.github/workflows/` matching `apply-*.yml` or
`restore-container-config*.yml`, read from `origin/main` at 40e2673 (2026-10-12).

Method. For every workflow: (a) triggers read from its `on:` block; (b) `grep -rn -F` for its stem and its `name:` across every
tracked file except `.git/`, `ci-status/` and `deployed-current.worker.js` mirrors, split into live references (a `workflow_run:`
list, a `uses:`, a `needs:`, a script that calls or dispatches it) and prose mentions (a comment or docstring, which is not a
dependency); (c) its effect, read from its `run:` steps; (d) its last run. Git history was squashed into one commit on
2026-10-11 (f091ab5, "ci(status): remediation-consumer"), so `git log -1` reads the same date for all 39 and carries no signal;
run evidence comes from `ci-status/*.json` and `audits/applier-doctor-2026-10-10.json`, whose 74 verdicts (70 already-applied,
1 error, 3 undetermined) were re-checked by grepping each marker on main.

Rule applied. KEEP: a live runner (apply-migrations, apply-pending-patches), a standing workflow with its own schedule or
`repository_dispatch` that other paths name, the one `restore-container-config*` workflow the standing container paths name, and
anything in doubt. FOLD: a spent applier that a live workflow still names in `workflow_run:`; the name is removed there in the
same change. DELETE: a one-shot applier with push + workflow_dispatch triggers whose patch text is present on main (or whose
target is FOLDED), with no live reference. The deleted appliers are idempotent: each prints "already applied" and exits
without committing, so deleting one whose patch is live changes nothing (docs/TRANSFORMATION-PROGRAM.md, step 8). The patch
scripts under `scripts/*patch*.py` stay; apply-pending-patches.yml runs them on every push that touches one.
