## Summary

FIX-EMPTY-BACKUP-ISSUE-1: Fixes the BACKUP-SELF-EMPTY-1 failure from PR #8537's migration `2026-11-07-fix-migration-schema-errors.sql`.

## Root Cause

PR #8537 attempted to create a BACKUP table using:
```sql
CREATE TABLE bak_20261107_remediation_contracts_companion_ui AS 
SELECT * FROM remediation_contracts WHERE class IN ('issue-8495-runtime', 'issue-8495-code');
```

This SELECT returns 0 rows because those classes don't exist yet (they were supposed to be created by the failed migration PR #8537 was trying to fix). The BACKUP-SELF-EMPTY-1 guard in apply-migrations correctly caught this - the backup table has 0 rows.

## Solution

Use INSERT OR REPLACE directly without BACKUP tables. These are **restorations of missing data**, not modifications of existing data, so there's nothing to back up. INSERT OR REPLACE is idempotent (safe to run multiple times).

## Breaking the Recursive Failure Cycle

This is the 3rd layer of a recursive migration failure:
1. Original migrations failed in production
2. PR #8506 created 5 migrations to fix those, but 4 failed with schema errors
3. PR #8537 created migration to fix PR #8506's failures, but failed with empty BACKUP table

This PR breaks the cycle by using the correct pattern for restoring missing data: INSERT OR REPLACE without BACKUP tables.
