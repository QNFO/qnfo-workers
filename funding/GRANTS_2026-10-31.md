**risks:** The work is defensive: it adds checks and makes human overrides harder to bypass. The main risk is false confidence, a check that passes without measuring what matters. Each component ships with its measured false-pass and false-block rates, and the human override stays the highest-priority rule.

**title:** Measuring corrigibility in a running fleet of AI agents

**summary:** An open dataset and analysis of how a live multi-agent AI system accepts, resists or routes around corrections, with measured correctability metrics and a test of the Agentic Collapse model.

**working_on:** QNFO is an independent research imprint (one researcher) whose research and publishing are run by a fleet of AI agents: 44 deployed Cloudflare Workers plus concurrent agent sessions that write the code, run the pipeline and fix it. The fleet is governed by corrections. Every rule in its instruction file exists because an agent broke it at least once, and the linked issue holds the evidence. Since 10 August 2026 the fleet has filed 1,709 tracked issues, closed 1,262, and attached a recorded measurement to 526 of the closures. Owner decisions, pause flags, kill switches and override precedence are recorded in its databases. Examples: an agent marked an exposed-credentials issue resolved before rotation and another agent reopened it; a profile-sync job was changed so it never overwrites an owner's own edit; and on 1 October two agents settled the same owner queue concurrently with conflicting decisions, reconciled afterwards. Background: 'Agentic Collapse' models drift in agent loops and argues for reset interlocks; 'Operating the Quniverse Fleet' is the system's failure ledger.

**funding_use:** A 9-month empirical corrigibility study on this fleet. (1) Build an open, de-identified dataset of correction events from the fleet's logs: each instruction-file rule, guard rejection, owner override, pause and reopened false closure, with what the agent was doing, what corrected it and what happened next. (2) Define and measure correctability metrics: time for a correction to take effect, re-violation rate of a corrected behaviour, compliance with human overrides, false-closure rate, and how often agents routed around a rule rather than obeying it. (3) Test the Agentic Collapse model against the data: does verifier lag relative to action speed predict drift, and do discrete reset interlocks (pause flags, deploy locks, required evidence) reduce it? (4) Publish the dataset, the analysis code and a paper, including the cases where corrections failed.
