## What was wrong

`scripts/apply_migrations.py` `plan()` returns `skip` for a migration without `-- APPLY-BY: ci`. `--check`, `apply-migrations.yml` and the
MIGRATION-UNAPPLIED sweep all read only opted-in files, so a migration that forgot its header passed every gate and was never applied.
`migrations/2026-10-18-subscribers-utm-attribution.sql` is the proof: two `ALTER TABLE subscribers ADD COLUMN` statements, no header,
no `migration_runs` row, and the live `subscribers` table has no `utm_source` or `utm_campaign` while qnfo-subscribers 1.3.3 selects them.

## What changed

- `python3 scripts/apply_migrations.py --check` now fails a file that has executable SQL (ALTER, CREATE, INSERT, UPDATE, DELETE, DROP,
  REPLACE; comments and a SELECT-only file do not count) and declares neither `-- APPLY-BY: ci` nor `-- APPLY-BY: manual (<reason>)` /
  `-- APPLY-BY: none (<reason>)`. The declaration must sit in the leading comment block, and the reason must not be empty.
- `ci` behaviour and `--apply` are untouched: a headerless file is still skipped at apply time.
- `migrations/headerless-allowlist.txt` grandfathers the files that already existed. It was generated by running the rule over
  `migrations/` on main (not picked by hand), is shrink-only, and expires 2026-11-19 (a lapsed list prints a warning on stderr; it never
  turns an unrelated PR red). `apply_migrations_test.py` fails while a listed file has gained a header, lost its SQL or been removed.
- Registered per DOCTRINE-1: `control_registry` rows `migration-header-guard` (gate, keep) and `migration-headerless-allowlist` (filter,
  demote), failure mode `migration-headerless-silent-skip` with detector contract `fm-migration-headerless-silent-skip`, and the
  follow-up issue `MIGRATION-HEADERLESS-AUDIT-1` whose closing probe is `code-probe: absent ".sql"` in the allowlist.

## Method and limits

Measured 2026-10-19 with D1 SELECT/PRAGMA on `qnfo-audit` only (`sqlite_master`, `pragma_table_info`). Objects were extracted from each file
with the runner's own statement splitter. "exists" means a table, view, trigger, index or column of that name is present in `qnfo-audit`; it
does not prove the live definition equals the file's. A file that only writes rows (INSERT/UPDATE/DELETE on existing tables) creates no
object, so its effect is not checked here. Other databases were not queried: a file whose objects belong elsewhere is marked
`unverifiable-here`. "Safe to apply" counts only files whose every statement is `CREATE ... IF NOT EXISTS` or `ADD COLUMN`
(ADD COLUMN on a column that already exists is a no-op in the runner, which tolerates "duplicate column name"). No old file was edited or applied.

Corrections to the earlier diagnosis:

1. The auditors counted 17 headerless files for 2026-10-16..18 and 95 on main in all. Measured: 95 headerless files, of which 93 hold
   executable SQL (the allowlist) and 2 hold none (`2026-10-01-evidence-contracts.sql`, `2026-10-19-close-probe-generator.sql`: comments only,
   no header needed). The first draft of the rule counted 91 and 4: it missed a statement that starts with WITH (a CTE insert), which
   `2026-10-02-ask-loop-triggers.sql` and `2026-10-02-work-with-me-triggers.sql` are; the rule now reads those as writes.
2. `2026-10-18-paper-tags.sql` and `2026-10-18-paper-audience-categories.sql` are not unapplied qnfo-audit migrations. qnfo-gateway
   reads `paper_tag`, `tag_registry` and `paper_category` through its `LIVING_PAPER` binding (`qnfo-gateway/worker.js`, living-paper
   `70a58cb3-b2cd-498d-877f-ecca86859a22`), and `qnfo-audit` has no `papers` table. They target living-paper, which the runner cannot reach
   (`DATABASES` holds only `qnfo-audit`), so they cannot become `APPLY-BY: ci`. Whether the tables exist in living-paper is
   unverifiable here; the gateway guards for a missing table.
3. `2026-10-06-project-state-second-collision.sql` shows `project_state_v2` absent only because the file renames it to `project_state`;
   live `project_state` has the new `snapshot_id` primary key, so it is applied.

## Decision per group (for the follow-up issue)

- Subscribers file: gets its header in the qnfo-subscribers batch and leaves the allowlist in the same pull request.
- 12 other safe files that are already live: add `-- APPLY-BY: manual (applied by hand 2026-10; objects verified live 2026-10-19)` or
  `ci` (idempotent, the runner records one `ok` run), then drop the name from the list.
- Row-writing and destructive files: declare `APPLY-BY: manual (<reason>)`; never `ci`, because a replay would re-run DELETE/DROP/UPDATE.
- `artifacts-canonical-sync`: the three missing indexes are a real gap; add a new `ci` migration with `CREATE INDEX IF NOT EXISTS`.
- living-paper files: declare `manual` with living-paper evidence, or extend `DATABASES` through a recorded change.
