## ipatent — CORRECTION: not a stall, it is a draft generator

`submissions`: **59 rows, all `status='draft'`**, newest 2026-09-11 14:38:00.

I initially read "59 drafts, nothing progressed" as a tenth stalled queue. **That is wrong**, and the
row contents refute it. Each submission's generated HTML carries:

```
<div class="watermark">DRAFT</div>
<h1>UNITED STATES PROVISIONAL PATENT DISCLOSURE</h1>
<p><strong>Status:</strong> DRAFT — Not yet filed with USPTO</p>
...
<p>Generated by ipatent.me — AI-Powered US Provisional Disclosure Tool</p>
<p>This is NOT a filed patent application. No USPTO filing date has been established.</p>
```

The product *is* a provisional-disclosure draft generator. `status='draft'` is its terminal state,
not a stuck one. All-draft is the expected steady state and there is no downstream stage to reach.

**What is genuinely notable** (data quality, not a fleet error):

| field | observed |
|---|---|
| `inventor_name` | `""` on sampled rows |
| `inventor_email` | `""` on sampled rows |
| `user_type` | `null` |
| rendered disclosure | "Inventor: Not provided" / "Contact: Not provided" |

So disclosures are generated and stored with no inventor identity attached, while real users are
driving it (distinct NL IPs, distinct `session_id`s, Chrome 152/153 UAs, `r2_key` per submission
under `disclosures/`). The generator runs; the metadata is not captured.
