# qnfo-fleet-dashboard

Task-Scheduler-style at-a-glance health view of the QNFO Cloudflare ecosystem.

URL: https://fleet.qnfo.org/  (mirror: https://qnfo-fleet-dashboard.q08.workers.dev/)  (JSON: /api/state, health: /health, force refresh: /api/refresh)

## What it shows
- Every scheduled worker (48 with cron triggers from CF Workers API), with crons, computed next UTC runs, 24h invocation + error counts (CF GraphQL), expected-fire checks ("NO-RUN" when expected fires > 0 but 0 invocations in 24h).
- D1 pipeline audits: deployments, errata queue/actions, AI gateway failures, agent issues, email store, ops AI gateway (ok-rate), AI model health, AI queries, living-paper counts, outreach pipeline state + sent_log, governance register owner=user open rows.
- Endpoint probes (top services /health).
- Device-bound front-end-only panel (Windows Task Scheduler + DeepChat local cron canonical rows) - captured by an ops cycle on the host; cloud-able functions never run as local cron (CLOUD-FRONTEND-ONLY-1).

## Refresh
- Cron trigger: every 15 min (cloud).
- /api/state auto-refreshes when state older than 15 min.
- Secret CF_TOKEN = Cloudflare API token with account analytics read (GraphQL). Set via: echo $CLOUDFLARE_API_TOKEN | wrangler secret put CF_TOKEN
- Registry (registry.js) is generated by an ops cycle from the CF Workers API /schedules endpoint + schtasks capture; re-run the generator script to refresh schedule metadata, then redeploy.

## Storage
- State cached in qnfo-audit D1 table fleet_dashboard_state (id=1) - no KV/R2 dependency.
